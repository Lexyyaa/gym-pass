# 요구사항 분석

> 과제 원문([00-assignment.md](00-assignment.md))을 설계 전에 분석한다.
> 설계 · 구현 · 결론은 쓰지 않는다.
> 결정이 필요한 지점을 전부 드러내는 것이 목적이다.

- 작성: `analyst` 에이전트
- 뒤 문서가 이 문서의 ID를 참조한다
  - `S-n` 원문 문장 → `02`의 요구사항 출처
  - `H-n` 숨은 요구사항 → `02`의 `NFR` · `FR`(파생) 또는 범위 밖
  - `C-n` 결정 항목 → 사용자가 정한 뒤 `02` §5의 `D-n`
- 확신이 없는 항목에는 `(확인 필요)`와 이유를 붙인다

## 3. 숨은 요구사항

### H-1. {요구사항 한 줄}

- 왜 필요한가: 
- 유도된 문장: S-

### 관점별 확인

<!-- 해당이 없으면 "해당 없음"과 이유를 적는다 -->

1. 같은 요청이 두 번 들어오는 경우 → H-
2. 외부 시스템 응답이 늦거나, 두 번 오거나, 순서가 바뀌는 경우 → H-
3. 처리 중 프로세스가 죽는 경우 → H-
4. 두 인스턴스가 같은 데이터를 동시에 집는 경우 → H-
5. 시간 경계 (월말 · 2월 · 자정 · 금지 시간대 직전 등) → H-
6. 데이터가 없거나 0인 경우 → H-
7. 이미 종료된 상태의 대상에 다시 이벤트가 오는 경우 → H-
8. 입력 목록 안에 같은 항목이 중복된 경우 → H-
9. 잘못된 입력이 서버 오류(500)로 새는 경우 → H-
